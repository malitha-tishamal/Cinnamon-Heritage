Cinnamon Heritage: Ultimate System Breakdown

Complete documentation of every page, every section, and every function across the User, Admin, and Backend environments.

1. Public Facing / User Pages

1.1 Main Landing Page (index.html)

Purpose: The primary storefront and brand showcase for customers.

Sections Breakdown:

  • Preloader: A spinning loader that masks the screen while data is fetched.
  • Navbar: Sticky glassmorphism header with smooth-scroll anchor links.
  • Hero (Slider/Banner): The main visual entrance. Contains dynamic titles and subtitles loaded from the database.
  • About Us: Details the history of the Galle estate with an immersive background.
  • Factory: Highlights processing capabilities and ISO certifications.
  • Process Steps: 5 interactive cards (Harvesting, Washing, Peeling, Drying, Packing).
  • Products (Shop): The core e-commerce grid showing available cinnamon products.
  • Quality Assurance: Static section detailing lab testing and purity.
  • Contact: A communication form and contact details (Address, Phone, Email).
  • Floating WhatsApp: A fixed button for instant chat routing.

1.2 Order & Checkout Page (checkout.html)

Purpose: The transactional portal where users finalize purchases.

Sections Breakdown:

  • Product Summary: Displays the selected item, image, available stock, and a quantity selector (+/-).
  • Financial Breakdown: Shows Subtotal, Discount deductions, Delivery Fee, and Final Total.
  • Shipping Form: Captures critical customer data (Name, Email, Phone, Province, District, Address).
  • Payment Selector: Radio buttons to choose between Cash on Delivery (COD), Bank Transfer, or Online Pay.
  • Bank Details Panel: Appears only if "Bank Transfer" is selected. Displays account numbers and a field for a reference slip.

2. Admin Portal & Management Pages

2.1 Dashboard (admin.html)

Purpose: The secure backend interface for the factory owner to manage all operations.

Sections Breakdown:

  • Auth Screens: Independent views for Login, Initial Setup, and Password Recovery.
  • Sidebar Navigation: The main menu to switch between management modules.
  • Stats Dashboard: Displays total earnings, order counts, unread messages, and a table showing best-selling products.
  • CMS Editor: Input forms corresponding to every text section on the public site (Hero, About, Factory, etc.).
  • Process Manager: Interface to alter the 5-step industrial process descriptions and images.
  • Inventory/Product Manager: The core CRUD interface to add new cinnamon products, set prices, apply discounts, and update stock limits.
  • Order Tracking: A tabular view of all historical and pending orders. Includes tools to view customer details and update delivery status.
  • Message Center: An inbox to read and resolve inquiries sent via the public Contact form.

3. Backend Infrastructure & API (server.js)

Purpose: The Node.js/Express engine that processes logic, connects to MySQL, and enforces security.

Core Middlewares:

  • express.json() Parses incoming request bodies (like order forms) into readable JSON.
  • express-session Generates a secure cookie (`maxAge: 1 year`) to keep the admin logged in safely without passing passwords continually.
  • multer Configured via `diskStorage` to intercept file uploads, rename them with timestamps to prevent overwrites, and save them to the `/images` folder.

Backend Functions & Routes:

Route / FunctionDetailed Backend Logic Execution
requireAuth()Custom middleware. Checks if `req.session.isAdmin` is true. If false, returns HTTP 401 Unauthorized, blocking access to all `/api/admin/*` routes.
POST /api/auth/loginQueries the `admin_users` table by email. If found, uses `bcrypt.compare()` to securely verify the hashed password. If true, sets `req.session.isAdmin = true`.
POST /api/auth/setupUses `bcrypt.hash(password, 10)` to encrypt the master password before inserting the first administrator into the database.
GET /api/contentQueries `SELECT * FROM site_content`. Restructures the flat SQL rows into a nested JSON object categorized by `section_name` for easy frontend parsing.
GET /api/productsExecutes an advanced SQL query featuring a `LEFT JOIN` on the `order_items` table. It uses `SUM(quantity)` to dynamically calculate how many units of a product have been sold (`total_sales`) alongside basic product data.
POST /api/ordersThe most complex logic: 1. Requests a dedicated connection (`pool.getConnection`).
2. Starts a MySQL `beginTransaction()`.
3. Checks `products` table to ensure `stock_quantity >= requested_quantity`.
4. Inserts into `orders` table to get the master `order_id`.
5. Inserts into `order_items` table for itemized tracking.
6. Executes `UPDATE products SET stock_quantity = stock_quantity - qty`.
7. Calls `connection.commit()`. If any step fails, calls `connection.rollback()` to prevent ghost data.
PUT /api/admin/contentUses a dual approach: Attempts an `UPDATE` query. If `affectedRows === 0` (meaning the content key doesn't exist yet), it executes an `INSERT` query. Ensures data always saves.
GET /api/admin/statsRuns 6 separate SQL queries concurrently to count total messages, active products, and total orders. Calculates earnings specifically for "Today" (`CURDATE()`), "This Month", and "Total Lifetime" while excluding "Cancelled" orders.
