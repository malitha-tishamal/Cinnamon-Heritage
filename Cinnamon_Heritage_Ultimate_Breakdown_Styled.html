1. Project Overview

The Cinnamon Heritage platform is a high-end, role-based web application designed to digitize the agricultural supply chain and retail operations of a Ceylon Cinnamon estate. It bridges the gap between traditional processing and modern digital commerce. The system features an immersive public storytelling interface, an automated e-commerce checkout with real-time stock management, and a robust administrative dashboard managing products, content (CMS), orders, and site settings.

4. Backend Infrastructure & API (server.js)

Purpose: The Node.js/Express engine that processes logic, connects to MySQL, and enforces security.

Core Middlewares:

  • express.json() Parses incoming request bodies (like order forms) into readable JSON.
  • express-session Generates a secure HTTP-only cookie (maxAge: 1 year) to keep the admin logged in safely without passing passwords continually.
  • multer Configured via diskStorage to intercept image uploads, rename them with timestamps to prevent overwrites, and save them securely to the /images folder.

Backend Functions & Routes:

Route / FunctionDetailed Backend Logic Execution
requireAuth()Custom middleware. Checks if req.session.isAdmin is true. If false, returns HTTP 401 Unauthorized, blocking access to all /api/admin/* routes.
POST /api/auth/loginQueries the admin_users table by email. If found, uses bcrypt.compare() to securely verify the hashed password. If true, sets req.session.isAdmin = true.
POST /api/auth/setupUses bcrypt.hash(password, 10) to encrypt the master password before inserting the first administrator into the database.
POST /api/auth/signup & /forgot-passwordSignup allows adding new admins. Forgot password implements a secure reset loop.
GET /api/content & /api/settingsQueries SELECT * FROM site_content and site_settings. Restructures the flat SQL rows into nested JSON objects for easy frontend consumption.
GET /api/productsExecutes an advanced SQL query featuring a LEFT JOIN on the order_items table. It uses SUM(quantity) to dynamically calculate how many units of a product have been sold (total_sales) alongside basic product data.
POST /api/ordersThe most complex logic (Database Transaction):
1. Requests a dedicated connection (pool.getConnection).
2. Starts a MySQL beginTransaction().
3. Checks products table to ensure stock_quantity >= requested_quantity.
4. Inserts into orders table to get the master order_id.
5. Inserts into order_items table for itemized tracking.
6. Executes UPDATE products SET stock_quantity = stock_quantity - qty.
7. Calls connection.commit(). If any step fails, calls connection.rollback() to prevent ghost data or negative stock.
PUT /api/admin/content & /settingsUses a dual approach: Attempts an UPDATE query. If affectedRows === 0 (meaning the content key doesn't exist yet), it executes an INSERT query. Ensures data always saves.
GET /api/admin/statsRuns 6 separate SQL queries concurrently to count total messages, active products, and total orders. Calculates earnings specifically for "Today" (CURDATE()), "This Month", and "Total Lifetime" while excluding "Cancelled" orders.
POST /api/contactInserts customer inquiries into the `contact_messages` table and optionally triggers EmailJS.
